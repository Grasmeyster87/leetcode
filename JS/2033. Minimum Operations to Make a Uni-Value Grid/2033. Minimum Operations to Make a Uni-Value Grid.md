2033. Minimum Operations to Make a Uni-Value Grid

Medium

<p>You are given a 2D integer <code>grid</code> of size <code>m x n</code> and an integer <code>x</code>. In one operation, you can <strong>add</strong> <code>x</code> to or <strong>subtract</strong> <code>x</code> from any element in the <code>grid</code>.</p>

### Пояснення рядок за рядком

#### Код
```js
/**
 * @param {number[][]} grid
 * @param {number} x
 * @return {number}
 */
var minOperations = function(grid, x) {
    const MAX = 10001;
    const freq = new Int32Array(MAX);
    const m = grid.length;
    const n = grid[0].length;
    const total = m * n;
    const remainder = grid[0][0] % x;

    for (let i = 0; i < m; i++) {
        for (let j = 0; j < n; j++) {
            const val = grid[i][j];
            if (val % x !== remainder) return -1;
            freq[val]++;
        }
    }

    // Знаходимо медіану через counting sort
    const medianPos = (total >> 1) + 1;
    let count = 0;
    let median = 0;
    for (let v = 0; v < MAX; v++) {
        count += freq[v];
        if (count >= medianPos) {
            median = v;
            break;
        }
    }

    // Рахуємо операції
    let ops = 0;
    for (let v = 0; v < MAX; v++) {
        if (freq[v] > 0) {
            ops += freq[v] * (Math.abs(v - median) / x);
        }
    }

    return ops;
};
```

#### Додаткові пояснення важливих моментів

- **Чому перевірка залишків стоїть перед підрахунком частот**  
  Це швидка перевірка можливості: якщо хоча б один елемент має інший залишок, немає сенсу продовжувати — відповідь `-1`.

- **Чому медіана**  
  Медіана мінімізує суму абсолютних відхилень, а оскільки кожна операція змінює значення на `x`, мінімізувати суму \(|v - t|\) еквівалентно мінімізувати кількість операцій.

- **Чому використано counting sort**  
  Щоб знайти медіану без сортування великого масиву: підрахунок частот і лінійний прохід по можливим значенням дає ефективний алгоритм при обмеженому діапазоні значень.

- **Чому ділення на x без округлення безпечно**  
  Тому що попередньо перевірено, що всі значення мають однаковий залишок при діленні на `x`, отже різниця `v - median` ділиться на `x` без залишку.

### Покроковий приклад на конкретній матриці

**Вхід:** `grid = [[2,4],[6,8]]`, `x = 2`  
**Мета:** знайти мінімальну кількість операцій ±x, щоб усі елементи стали рівними або повернути `-1`, якщо неможливо.

1. **Ініціалізація змінних**
   - `m = 2`, `n = 2`, `total = m * n = 4`.
   - `remainder = grid[0][0] % x = 2 % 2 = 0`.

2. **Перевірка залишків і підрахунок частот**
   - Проходимо всі елементи по рядках і стовпцях:
     - `val = 2`. `2 % 2 = 0` збігається з `remainder`. Збільшуємо `freq[2]`.
     - `val = 4`. `4 % 2 = 0` збігається. Збільшуємо `freq[4]`.
     - `val = 6`. `6 % 2 = 0` збігається. Збільшуємо `freq[6]`.
     - `val = 8`. `8 % 2 = 0` збігається. Збільшуємо `freq[8]`.
   - Жодного елемента з іншим залишком немає, отже перетворення можливе.

3. **Знаходження медіани через масив частот**
   - `medianPos = (total >> 1) + 1 = (4 >> 1) + 1 = 2 + 1 = 3`.
   - Проходимо `v` від 0 до `MAX` і накопичуємо `count = count + freq[v]`:
     - при `v = 2` `count = 1`.
     - при `v = 4` `count = 2`.
     - при `v = 6` `count = 3` — `count >= medianPos`, отже **median = 6**.
   - Примітка про вибір: для парної кількості елементів можна вибрати верхню або нижню медіану. Обидва варіанти дають мінімум сумарних абсолютних відхилень у кроках по `x`.

4. **Підрахунок операцій**
   - Для кожного значення `v` з ненульовою частотою додаємо `freq[v] * (|v - median| / x)`:
     - `v = 2`: `freq[2] * (|2 - 6| / 2) = 1 * (4 / 2) = 2`.
     - `v = 4`: `1 * (|4 - 6| / 2) = 1 * (2 / 2) = 1`.
     - `v = 6`: `1 * (|6 - 6| / 2) = 0`.
     - `v = 8`: `1 * (|8 - 6| / 2) = 1 * (2 / 2) = 1`.
   - **Сума операцій = 2 + 1 + 0 + 1 = 4**.

5. **Результат**
   - Функція повертає `4`.

### Альтернативна реалізація через шкалювання значень на x
Замість роботи з оригінальними значеннями можна поділити всі значення на `x` і працювати з цілими числами. Тоді одна операція відповідає зміні на `±1`. Це спрощує інтуїцію і дозволяє використовувати звичайний пошук медіани.

#### Код JavaScript зі шкалюванням і сортуванням
```js
var minOperations = function(grid, x) {
  const arr = [];
  const m = grid.length;
  const n = grid[0].length;
  const remainder = grid[0][0] % x;

  for (let i = 0; i < m; i++) {
    for (let j = 0; j < n; j++) {
      const v = grid[i][j];
      if (v % x !== remainder) return -1;
      arr.push(v / x);
    }
  }

  arr.sort((a, b) => a - b);
  const mid = arr[Math.floor(arr.length / 2)];
  let ops = 0;
  for (let v of arr) {
    ops += Math.abs(v - mid);
  }
  return ops;
};
```

#### Пояснення коду рядок за рядком
- Збираємо всі `v / x` у масив `arr` після перевірки однакових залишків.
- Сортуємо `arr` і беремо **медіану** як `arr[Math.floor(arr.length / 2)]`.
- Сумуємо абсолютні відхилення `|v' - median'|`. Це дає кількість одиничних кроків, тобто кількість операцій ±x у початкових одиницях.
- Повертаємо суму `ops`.

---

### Порівняння підходів і коли який краще
- **Counting sort по значеннях** підходить, коли значення обмежені `<= 10000`. Перевага — не потрібно виділяти пам’ять під весь список і не потрібно сортування `O(N log N)`.
- **Шкалювання + сортування** простіше для розуміння і працює добре при `mn` до `10^5`. Часова складність `O(mn log(mn))`. Пам’ять `O(mn)`.

---

### Коротке резюме
- Перевірка однакових залишків при діленні на `x` — обов’язкова.
- Оптимальна ціль — **медіана** значень або медіана значень, поділених на `x`.
- Кількість операцій = сума \(\frac{|v - \text{median}|}{x}\) або сума \(|v' - \text{median}'|\) після шкалювання.

### Пояснення `const medianPos = (total >> 1) + 1;`

**Що робить `>> 1`**  
`total >> 1` — це побітовий зсув вправо на 1 біт, який еквівалентний цілої частини від ділення на 2: \(\lfloor \tfrac{\text{total}}{2}\rfloor\).

**Навіщо додають `+1`**  
Додавання `+1` перетворює результат у **1‑індексовану позицію медіани** і при парній кількості елементів вибирає **верхню медіану**. Тобто
\[
\text{medianPos} = \left\lfloor\frac{\text{total}}{2}\right\rfloor + 1.
\]

**Приклади**
- Якщо \(\text{total}=5\): \(\text{total}>>1 = 2\), \(\text{medianPos}=3\). Це третій елемент у впорядкованому списку — звичайна медіана.
- Якщо \(\text{total}=4\): \(\text{total}>>1 = 2\), \(\text{medianPos}=3\). Це **третій** елемент у впорядкованому списку (верхня з двох середніх позицій).

**Чому вибір верхньої медіани допустимий**  
Для мінімізації суми абсолютних відхилень будь-яке значення між двома середніми (включно з нижньою або верхньою медіаною) дає однакову мінімальну суму. Тому вибір позиції \(\lfloor\frac{\text{total}}{2}\rfloor+1\) — простий і коректний.

**Як це працює з `freq`**  
Цикл накопичує `count += freq[v]` і зупиняється при `count >= medianPos`. Оскільки `medianPos` — 1‑індексована позиція у впорядкованому наборі, перше `v`, при якому накопичення досягає цієї позиції, і є медіаною.

**Альтернативи**  
Можна було б використовувати нуль‑індексну позицію медіани як `Math.floor(total/2)` і перевіряти `count > medianIndex`, але реалізація з `+1` робить умову `count >= medianPos` інтуїтивно простою.

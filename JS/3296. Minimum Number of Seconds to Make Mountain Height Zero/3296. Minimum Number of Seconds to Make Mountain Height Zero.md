Hint

You are given an integer mountainHeight denoting the height of a mountain.

You are also given an integer array workerTimes representing the work time of workers in seconds.

The workers work simultaneously to reduce the height of the mountain. For worker i:

    To decrease the mountain's height by x, it takes workerTimes[i] + workerTimes[i] * 2 + ... + workerTimes[i] * x seconds. For example:
        To reduce the height of the mountain by 1, it takes workerTimes[i] seconds.
        To reduce the height of the mountain by 2, it takes workerTimes[i] + workerTimes[i] * 2 seconds, and so on.

Return an integer representing the minimum number of seconds required for the workers to make the height of the mountain 0.

 

Example 1:

Input: mountainHeight = 4, workerTimes = [2,1,1]

Output: 3

Explanation:

One way the height of the mountain can be reduced to 0 is:

    Worker 0 reduces the height by 1, taking workerTimes[0] = 2 seconds.
    Worker 1 reduces the height by 2, taking workerTimes[1] + workerTimes[1] * 2 = 3 seconds.
    Worker 2 reduces the height by 1, taking workerTimes[2] = 1 second.

Since they work simultaneously, the minimum time needed is max(2, 3, 1) = 3 seconds.

Example 2:

Input: mountainHeight = 10, workerTimes = [3,2,2,4]

Output: 12

Explanation:

    Worker 0 reduces the height by 2, taking workerTimes[0] + workerTimes[0] * 2 = 9 seconds.
    Worker 1 reduces the height by 3, taking workerTimes[1] + workerTimes[1] * 2 + workerTimes[1] * 3 = 12 seconds.
    Worker 2 reduces the height by 3, taking workerTimes[2] + workerTimes[2] * 2 + workerTimes[2] * 3 = 12 seconds.
    Worker 3 reduces the height by 2, taking workerTimes[3] + workerTimes[3] * 2 = 12 seconds.

The number of seconds needed is max(9, 12, 12, 12) = 12 seconds.

Example 3:

Input: mountainHeight = 5, workerTimes = [1]

Output: 15

Explanation:

There is only one worker in this example, so the answer is workerTimes[0] + workerTimes[0] * 2 + workerTimes[0] * 3 + workerTimes[0] * 4 + workerTimes[0] * 5 = 15.

 

Constraints:

    1 <= mountainHeight <= 105
    1 <= workerTimes.length <= 104
    1 <= workerTimes[i] <= 106

Проблема, через яку ти отримуєш **Time Limit Exceeded (TLE)** на великих тестах, пов'язана не з ефективністю алгоритму, а з **втратою точності чисел у JavaScript**.

### Чому виникає TLE?

У JavaScript всі числа (тип `Number`) є 64-бітними числами з плаваючою комою. Вони можуть точно представляти цілі числа лише до `9,007,199,254,740,991` (`Number.MAX_SAFE_INTEGER`).

У твоєму тест-кейсі `mountainHeight = 100000`, `workerTimes = [1000000]`, значення `time` на певних кроках бінарного пошуку сягає $5 \cdot 10^{15}$. Коли у функції `canFinish` ти рахуєш `(8 * time)`, результат стає $40 \cdot 10^{15}$, що значно перевищує безпечний ліміт. Через це:

1. Втрачається точність обчислень.
2. `Math.sqrt` повертає некоректне значення.
3. Бінарний пошук "зациклюється", оскільки змінні `left` та `right` припиняють правильно оновлюватися, що і викликає нескінченний цикл (TLE).

### Як це виправити?

Нам потрібно використати тип **`BigInt`**, який дозволяє працювати з цілими числами будь-якого розміру. Оскільки для `BigInt` немає вбудованого `Math.sqrt`, ми знайдемо наближене значення через звичайний `Number`, а потім скоригуємо його на $\pm 1$ за допомогою циклу `while`.

Також, для оптимізації верхньої межі (`right`) краще використовувати час **найшвидшого** працівника, а не максимальний, оскільки в найгіршому випадку саме найшвидший працівник зможе виконати всю роботу сам.

Ось виправлений та оптимізований код:

```javascript
/**
 * @param {number} mountainHeight
 * @param {number[]} workerTimes
 * @return {number}
 */
var minNumberOfSeconds = function (mountainHeight, workerTimes) {
    let mH = BigInt(mountainHeight);

    // Шукаємо найменший час виконання (найшвидшого працівника)
    let minTime = BigInt(workerTimes[0]);
    for (let i = 1; i < workerTimes.length; i++) {
        if (BigInt(workerTimes[i]) < minTime) {
            minTime = BigInt(workerTimes[i]);
        }
    }

    let left = 1n;
    // Найгірший варіант: найшвидший працівник робить усю роботу
    let right = (minTime * mH * (mH + 1n)) / 2n;
    let ans = right;

    function canFinish(time) {
        let totalHeight = 0n;
        for (let i = 0; i < workerTimes.length; i++) {
            let t = BigInt(workerTimes[i]);
            
            // Базова формула: k * (k + 1) <= 2 * time / t
            let val = (2n * time) / t;

            // Наближене значення k. 
            // Конвертуємо у Number лише для приблизного кореня.
            let k = BigInt(Math.floor(Math.sqrt(Number(val))));

            // Точне коригування k (виправляє можливу похибку Number)
            while (k * (k + 1n) > val) {
                k--;
            }
            while ((k + 1n) * (k + 2n) <= val) {
                k++;
            }

            totalHeight += k;

            // Ранній вихід: якщо вже розчистили гору, немає сенсу перевіряти інших
            if (totalHeight >= mH) {
                return true;
            }
        }
        return false;
    }

    while (left <= right) {
        let mid = (left + right) / 2n;
        if (canFinish(mid)) {
            ans = mid;
            right = mid - 1n;
        } else {
            left = mid + 1n;
        }
    }

    // Відповідь безпечно повертати як Number, бо вона поміщається у MAX_SAFE_INTEGER
    return Number(ans);
};

```

### Що змінилося:

1. **`BigInt`**: Дозволяє уникнути переповнення та нескінченних циклів.
2. **Оптимізована межа `right**`: Використано `minTime` замість `maxTime`, що відчутно скорочує простір пошуку.
3. **Ранній вихід (Early return)**: Як тільки `totalHeight` досягає або перевищує висоту гори, функція повертає `true`, не ітеруючи залишок масиву працівників.

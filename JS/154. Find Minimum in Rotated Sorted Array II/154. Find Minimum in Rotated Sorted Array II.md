154. Find Minimum in Rotated Sorted Array II

Hard
<p>Suppose an array of length <code>n</code> sorted in ascending order is <strong>rotated</strong> between <code>1</code> and <code>n</code> times. For example, the array <code>nums = [0,1,4,4,5,6,7]</code> might become:</p>

<ul>
	<li><code>[4,5,6,7,0,1,4]</code> if it was rotated <code>4</code> times.</li>
	<li><code>[0,1,4,4,5,6,7]</code> if it was rotated <code>7</code> times.</li>
</ul>

<p>Notice that <strong>rotating</strong> an array <code>[a[0], a[1], a[2], ..., a[n-1]]</code> 1 time results in the array <code>[a[n-1], a[0], a[1], a[2], ..., a[n-2]]</code>.</p>

<p>Given the sorted rotated array <code>nums</code> that may contain <strong>duplicates</strong>, return <em>the minimum element of this array</em>.</p>

<p>You must decrease the overall operation steps as much as possible.</p>

<p>&nbsp;</p>
<p><strong class="example">Example 1:</strong></p>
<pre><strong>Input:</strong> nums = [1,3,5]
<strong>Output:</strong> 1
</pre><p><strong class="example">Example 2:</strong></p>
<pre><strong>Input:</strong> nums = [2,2,2,0,1]
<strong>Output:</strong> 0
</pre>
<p>&nbsp;</p>
<p><strong>Constraints:</strong></p>

<ul>
	<li><code>n == nums.length</code></li>
	<li><code>1 &lt;= n &lt;= 5000</code></li>
	<li><code>-5000 &lt;= nums[i] &lt;= 5000</code></li>
	<li><code>nums</code> is sorted and rotated between <code>1</code> and <code>n</code> times.</li>
</ul>

154. Нахождение минимума в повернутом отсортированном массиве II

Сложно
<p>Предположим, массив длиной <code>n</code>, отсортированный в порядке возрастания, <strong>поворачивается</strong> от <code>1</code> до <code>n</code> раз. Например, массив <code>nums = [0,1,4,4,5,6,7]</code> может стать следующим:</p>

<ul>

<li><code>[4,5,6,7,0,1,4]</code>, если его повернуть <code>4</code> раза.</li>

<li><code>[0,1,4,4,5,6,7]</code>, если его повернуть <code>7</code> раз.</li>
</ul>

<p>Обратите внимание, что <strong>поворот</strong> массива <code>[a[0], a[1], a[2], ..., a[n-1]]</code> 1 раз приводит к массиву <code>[a[n-1], a[0], a[1], a[2], ..., a[n-2]]</code>.</p>

<p>Дано отсортированное повернутое множество <code>nums</code>, которое может содержать <strong>дубликаты</strong>, вернуть <em>минимальный элемент этого массива</em>.</p>

<p>Необходимо максимально сократить общее количество шагов операции.</p>

<p>&nbsp;</p>
<p><strong class="example">Пример 1:</strong></p>
<pre><strong>Входные данные:</strong> nums = [1,3,5]
<strong>Выходные данные:</strong> 1
</pre><p><strong class="example">Пример 2:</strong></p>
<pre><strong>Входные данные:</strong> nums = [2,2,2,0,1]
<strong>Выходные данные:</strong> 0
</pre>
<p>&nbsp;</p>

<ul>

<li><code>n == nums.length</code></li>

<li><code>1 <= n <= 5000</code></li>

<li><code>-5000 <= nums[i] <= 5000</code></li>

<li><code>nums</code> отсортирован и повернут между <code>1</code> и <code>n</code> раз.</li>
</ul>

## Пояснення розв'язку

### Алгоритм: Модифікований бінарний пошук

Задача є ускладненням задачі **153 (без дублікатів)**. Основна ідея залишається тією ж — **бінарний пошук**, але дублікати створюють ситуацію неоднозначності, яку потрібно обробити окремо.

### Ключова ідея

У повернутому відсортованому масиві мінімум — це точка «злому», де порядок порушується. Ми порівнюємо `nums[mid]` з `nums[right]`, щоб визначити, в якій половині масиву знаходиться мінімум.

### Три випадки порівняння `nums[mid]` з `nums[right]`

| Випадок | Дія | Чому |
|---|---|---|
| `nums[mid] > nums[right]` | `left = mid + 1` | Злом (мінімум) гарантовано у правій частині. `mid` точно НЕ мінімум, бо є менше значення правіше. |
| `nums[mid] < nums[right]` | `right = mid` | Мінімум у лівій частині або це сам `mid`. Не можемо виключити `mid`, тому `right = mid` (не `mid - 1`). |
| `nums[mid] === nums[right]` | `right--` | **Дублікати!** Неможливо визначити сторону. Але `right` можна безпечно відкинути, бо `mid` має те ж значення і залишається в діапазоні. |

### Чому порівнюємо саме з `nums[right]`, а не з `nums[left]`?

Порівняння з `nums[left]` не працює коректно. Наприклад, для `[3, 4, 5, 1, 2]`:
- `left=0, right=4, mid=2` → `nums[mid]=5 > nums[left]=3`, але мінімум **праворуч**.
- Порівняння з `nums[left]` дало б хибний висновок, що ліва частина відсортована і мінімум `= nums[left]`.

З `nums[right]`: `nums[mid]=5 > nums[right]=2` → правильно зсуваємо `left = mid + 1`.

### Покрокові приклади

**Приклад 1:** `nums = [2, 2, 2, 0, 1]`

```
Крок 1: left=0, right=4, mid=2
  nums[2]=2 > nums[4]=1 → left = 3

Крок 2: left=3, right=4, mid=3
  nums[3]=0 < nums[4]=1 → right = 3

left === right === 3 → Відповідь: nums[3] = 0 ✓
```

**Приклад 2 (гірший випадок з дублікатами):** `nums = [1, 1, 1, 1, 1, 0, 1]`

```
Крок 1: left=0, right=6, mid=3
  nums[3]=1 === nums[6]=1 → right = 5

Крок 2: left=0, right=5, mid=2
  nums[2]=1 > nums[5]=0 → left = 3

Крок 3: left=3, right=5, mid=4
  nums[4]=1 > nums[5]=0 → left = 5

left === right === 5 → Відповідь: nums[5] = 0 ✓
```

### Складність

| | В середньому | Найгірший випадок |
|---|---|---|
| **Час** | O(log n) | O(n) — коли всі елементи однакові, крім одного |
| **Пам'ять** | O(1) | O(1) |

**Чому найгірший випадок O(n)?** — Коли `nums[mid] === nums[right]`, ми зменшуємо діапазон лише на 1 елемент (`right--`). Для масиву `[1,1,1,...,1,0,1]` це деградує до лінійного пошуку. Це **неминуча** ціна дублікатів — доведено, що задачу з дублікатами неможливо вирішити швидше за O(n) у найгіршому випадку.

### Порівняння з задачею 153 (без дублікатів)

У задачі 153 немає гілки `nums[mid] === nums[right]`, і складність завжди **O(log n)**. Дублікати додають лише одну гілку, але кардинально змінюють найгіршу складність.

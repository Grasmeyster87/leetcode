3559. Number of Ways to Assign Edge Weights II

Hard
<p>There is an undirected tree with <code>n</code> nodes labeled from 1 to <code>n</code>, rooted at node 1. The tree is represented by a 2D integer array <code>edges</code> of length <code>n - 1</code>, where <code>edges[i] = [u<sub>i</sub>, v<sub>i</sub>]</code> indicates that there is an edge between nodes <code>u<sub>i</sub></code> and <code>v<sub>i</sub></code>.</p>

<p>Initially, all edges have a weight of 0. You must assign each edge a weight of either <strong>1</strong> or <strong>2</strong>.</p>

<p>The <strong>cost</strong> of a path between any two nodes <code>u</code> and <code>v</code> is the total weight of all edges in the path connecting them.</p>

<p>You are given a 2D integer array <code>queries</code>. For each <code>queries[i] = [u<sub>i</sub>, v<sub>i</sub>]</code>, determine the number of ways to assign weights to edges <strong>in the path</strong> such that the cost of the path between <code>u<sub>i</sub></code> and <code>v<sub>i</sub></code> is <strong>odd</strong>.</p>

<p>Return an array <code>answer</code>, where <code>answer[i]</code> is the number of valid assignments for <code>queries[i]</code>.</p>

<p>Since the answer may be large, apply <strong>modulo</strong> <code>10<sup>9</sup> + 7</code> to each <code>answer[i]</code>.</p>

<p><strong>Note:</strong> For each query, disregard all edges <strong>not</strong> in the path between node <code>u<sub>i</sub></code> and <code>v<sub>i</sub></code>.</p>

## Детальний розбір розв'язку

### 1. Математична ідея

Кожному ребру на шляху потрібно присвоїти вагу **1** або **2**. Нам потрібно, щоб **сума** всіх ваг на шляху була **непарною**.

**Ключове спостереження:** парність суми залежить лише від парності кожного доданка.
- Вага `1` → **непарна** (вносить `1` в парність).
- Вага `2` → **парна** (вносить `0` в парність).

Отже, сума непарна тоді й тільки тоді, коли серед `k` ребер **непарна кількість** має вагу `1`.

Кількість способів обрати непарну кількість одиниць з `k` елементів:

```
C(k,1) + C(k,3) + C(k,5) + ... = 2^(k-1)
```

> **Доведення:** з біноміальної теореми `(1+1)^k = Σ C(k,i)` та `(1-1)^k = Σ (-1)^i · C(k,i)`.
> Додаючи: `2^k = 2·(C(k,0) + C(k,2) + ...)` → сума парних = сума непарних = `2^(k-1)`.

**Особливі випадки:**
- `k = 0` (вузол = самому собі) → відповідь `0` (сума = 0, парна, жодного способу).
- `k ≥ 1` → відповідь `2^(k-1) mod (10^9 + 7)`.

**Залишилося ефективно знаходити `k`** — кількість ребер на шляху між `u` і `v` у дереві.

---

### 2. Знаходження довжини шляху через LCA

У дереві шлях між `u` та `v` єдиний і проходить через їхнього **найменшого спільного предка (LCA)**.

```
k = depth[u] + depth[v] - 2 · depth[LCA(u, v)]
```

Для ефективного обчислення LCA використовується алгоритм **Binary Lifting** — попередня обробка `O(n log n)`, кожен запит `O(log n)`.

---

### 3. Огляд алгоритму

| Етап | Що робимо | Складність |
|------|-----------|------------|
| 1 | Побудова CSR-списку суміжності | O(n) |
| 2 | BFS від кореня → `depth[]`, `parent[]` | O(n) |
| 3 | Binary Lifting таблиця `up[k][v]` | O(n log n) |
| 4 | Попередній обрахунок `pow2[]` | O(n) |
| 5 | Відповідь на кожен запит: LCA + формула | O(q log n) |

**Загальна складність:** `O((n + q) · log n)` за часом, `O(n log n)` за пам'яттю.

---

#### Рядки 6–9: Ініціалізація констант

```javascript
var assignEdgeWeights = function(edges, queries) {
    const MOD = 1000000007n;        // модуль як BigInt
    const n = edges.length + 1;     // кількість вузлів (ребер = n-1)
    const LOG = Math.ceil(Math.log2(n + 1)) + 1; // глибина таблиці Binary Lifting
```

- `MOD` — модуль `10^9 + 7` як BigInt для точної модульної арифметики.
- `n` — дерево з `n-1` ребрами має `n` вузлів.
- `LOG` — максимальна кількість бітів для представлення глибини дерева. Для `n = 10^5` це ≈ 17-18. Визначає висоту таблиці `up[]`.

#### Рядки 11–28: Побудова CSR-списку суміжності

```javascript
    const head = new Int32Array(n + 1).fill(-1);  // голова зв'язного списку для кожного вузла
    const to = new Int32Array(n * 2);              // куди веде ребро
    const nxt = new Int32Array(n * 2);             // наступне ребро в списку
    let edgeCnt = 0;                               // лічильник ребер
```

**CSR (Compressed Sparse Row)** — ефективна структура для зберігання графа:
- `head[u]` — індекс **першого** ребра вузла `u` (або `-1`, якщо ребер немає).
- `to[e]` — куди веде ребро з індексом `e`.
- `nxt[e]` — індекс **наступного** ребра того ж вузла (зв'язний список).

```javascript
    for (let i = 0; i < edges.length; i++) {
        const u = edges[i][0];
        const v = edges[i][1];

        // Додаємо ребро u → v
        to[edgeCnt] = v;
        nxt[edgeCnt] = head[u];      // нове ребро вказує на попереднє перше
        head[u] = edgeCnt++;          // тепер голова — нове ребро

        // Додаємо ребро v → u (неорієнтоване дерево)
        to[edgeCnt] = u;
        nxt[edgeCnt] = head[v];
        head[v] = edgeCnt++;
    }
```

Кожне неорієнтоване ребро додається двічі (u→v та v→u), тому масиви мають розмір `n*2`.

**Приклад:** для ребер `[[1,2],[1,3]]`:
```
head[1] = 2 → nxt[2] = 0 → nxt[0] = -1    (ребра 1→3, 1→2)
head[2] = 1 → nxt[1] = -1                   (ребро 2→1)
head[3] = 3 → nxt[3] = -1                   (ребро 3→1)
```

Обхід сусідів вузла `u`: `for (let e = head[u]; e !== -1; e = nxt[e])` → `to[e]`.

#### Рядки 30–54: BFS для обчислення глибини та батька

```javascript
    const depth = new Int32Array(n + 1);   // глибина кожного вузла від кореня
    const parent = new Int32Array(n + 1);  // прямий батько кожного вузла
    const order = new Int32Array(n);       // черга BFS (масив замість Queue)
    let qH = 0, qT = 0;                   // голова і хвіст черги

    parent[1] = -1;    // корінь не має батька (тимчасово -1)
    depth[1] = 0;      // глибина кореня = 0
    order[qT++] = 1;   // кладемо корінь в чергу
```

BFS від кореня (вузол 1) обходить дерево пошарово:

```javascript
    while (qH < qT) {
        const u = order[qH++];                           // беремо вузол з черги
        for (let e = head[u]; e !== -1; e = nxt[e]) {    // обходимо всіх сусідів
            const v = to[e];
            if (v !== parent[u] && parent[v] === 0 && v !== 1) {
                // v ще не відвіданий і це не батько u
                parent[v] = u;             // запам'ятовуємо батька
                depth[v] = depth[u] + 1;   // глибина = батько + 1
                order[qT++] = v;           // додаємо в чергу
            }
        }
    }
```

**Перевірка `v !== parent[u] && parent[v] === 0 && v !== 1`:**
- `v !== parent[u]` — не повертаємося до батька.
- `parent[v] === 0 && v !== 1` — вузол ще не відвіданий (parent = 0 означає "ще не встановлено", крім самого вузла 1).

```javascript
    parent[1] = 1;  // корінь вказує на себе для коректної роботи Binary Lifting
```

Після BFS виставляємо `parent[1] = 1` (self-loop). Це потрібно, щоб при піднятті вище кореня алгоритм не виходив за межі масиву — корінь залишиться на місці.

#### Рядки 56–72: Binary Lifting таблиця

```javascript
    const up = new Array(LOG);                  // up[k] — масив 2^k-х предків
    for (let k = 0; k < LOG; k++) {
        up[k] = new Int32Array(n + 1);          // виділяємо пам'ять
    }
```

`up[k][v]` = предок вузла `v` на відстані `2^k` кроків вгору.

```javascript
    // Базовий випадок: 2^0 = 1-й предок = прямий батько
    for (let i = 0; i <= n; i++) {
        up[0][i] = parent[i];
    }
```

```javascript
    // Рекурентність: 2^k-й предок = 2^(k-1)-й предок від 2^(k-1)-го предка
    for (let k = 1; k < LOG; k++) {
        for (let v = 1; v <= n; v++) {
            up[k][v] = up[k - 1][up[k - 1][v]];
        }
    }
```

**Ідея:** щоб піднятися на `2^k` кроків, спочатку піднімаємося на `2^(k-1)`, а потім ще на `2^(k-1)`.

**Приклад для дерева 1→2→3→4→5 (лінійне):**
```
up[0] = [_, 1, 1, 2, 3, 4]   ← прямі батьки
up[1] = [_, 1, 1, 1, 2, 3]   ← 2-й предок
up[2] = [_, 1, 1, 1, 1, 1]   ← 4-й предок
```

#### Рядки 74–95: Функція LCA (Найменший Спільний Предок)

```javascript
    function lca(u, v) {
        // Крок 1: забезпечуємо depth[u] >= depth[v]
        if (depth[u] < depth[v]) { let t = u; u = v; v = t; }
```

Спочатку робимо так, щоб `u` був глибше (або на тій же глибині).

```javascript
        // Крок 2: піднімаємо u до глибини v
        let diff = depth[u] - depth[v];
        for (let k = 0; diff > 0; k++, diff >>= 1) {
            if (diff & 1) u = up[k][u];   // якщо k-й біт різниці = 1, стрибаємо
        }
```

**Ідея:** різницю глибин розкладаємо в двійкову систему і робимо стрибки відповідних степенів двійки. Наприклад, `diff = 5 = 101₂` → стрибаємо на `2^0 = 1` і `2^2 = 4`.

```javascript
        // Крок 3: якщо вузли вже збіглися — це LCA
        if (u === v) return u;
```

Це відбувається, коли один вузол є предком іншого.

```javascript
        // Крок 4: піднімаємо обидва вузли синхронно
        for (let k = LOG - 1; k >= 0; k--) {
            if (up[k][u] !== up[k][v]) {   // якщо 2^k-ті предки різні
                u = up[k][u];              // обидва стрибають вгору
                v = up[k][v];
            }
        }
```

Ідемо від найбільшого стрибка до найменшого. Стрибаємо **тільки якщо предки різні** — щоб не "перестрибнути" LCA. Після циклу `u` і `v` будуть **дітьми** LCA.

```javascript
        return up[0][u];   // батько = LCA
    }
```

#### Рядки 97–108: Попередній обрахунок степенів двійки

```javascript
    let maxDepth = 0;
    for (let i = 1; i <= n; i++) {
        if (depth[i] > maxDepth) maxDepth = depth[i];
    }
    const maxLen = maxDepth * 2;   // максимальна довжина шляху = 2 × maxDepth
```

Найдовший шлях у дереві = від найглибшого вузла до іншого найглибшого = `2 × maxDepth`.

```javascript
    const pow2 = new BigInt64Array(maxLen + 1);
    pow2[0] = 1n;                                    // 2^0 = 1
    for (let i = 1; i <= maxLen; i++) {
        pow2[i] = (pow2[i - 1] * 2n) % MOD;         // 2^i mod (10^9+7)
    }
```

Заздалегідь рахуємо всі потрібні степені двійки за модулем. Це дозволяє відповідати на запити за `O(1)` замість `O(log k)` для швидкого піднесення до степеня.

```javascript
        // Особливий випадок: вузол до самого себе
        if (u === v) {
            ans[i] = 0;   // 0 ребер → сума = 0 (парна) → 0 способів
            continue;
        }
```

```javascript
        const l = lca(u, v);                              // знаходимо LCA
        const k = depth[u] + depth[v] - 2 * depth[l];     // кількість ребер на шляху
```

**Формула:** шлях u→LCA має `depth[u] - depth[LCA]` ребер, шлях v→LCA має `depth[v] - depth[LCA]` ребер. Разом: `depth[u] + depth[v] - 2·depth[LCA]`.

```javascript
        if (k === 0) {
            ans[i] = 0;                        // 0 ребер → 0 способів
        } else {
            ans[i] = Number(pow2[k - 1]);      // 2^(k-1) mod (10^9+7)
        }
    }

    return ans;
};
```

### 5. Чому це працює на прикладі

**Приклад 2:** дерево `1-2, 1-3, 3-4, 3-5`. Глибини: `{1:0, 2:1, 3:1, 4:2, 5:2}`.

| Запит | Шлях | LCA | k = ребер | Відповідь = 2^(k-1) |
|-------|------|-----|-----------|---------------------|
| [1,4] | 1→3→4 | 1 | 0+2-2·0=2 | 2^1 = **2** |
| [3,4] | 3→4 | 3 | 1+2-2·1=1 | 2^0 = **1** |
| [2,5] | 2→1→3→5 | 1 | 1+2-2·0=3 | 2^2 = **4** |

### 6. Складність

- **Час:** `O((n + q) · log n)` — побудова таблиці + обробка запитів.
- **Пам'ять:** `O(n · log n)` — таблиця Binary Lifting домінує.

Для `n = q = 10^5` це приблизно `10^5 × 17 ≈ 1.7 × 10^6` операцій — працює швидко.

33. Search in Rotated Sorted Array

Medium
<p>There is an integer array <code>nums</code> sorted in ascending order (with <strong>distinct</strong> values).</p>

<p>Prior to being passed to your function, <code>nums</code> is <strong>possibly left rotated</strong> at an unknown index <code>k</code> (<code>1 &lt;= k &lt; nums.length</code>) such that the resulting array is <code>[nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]]</code> (<strong>0-indexed</strong>). For example, <code>[0,1,2,4,5,6,7]</code> might be left rotated by&nbsp;<code>3</code>&nbsp;indices and become <code>[4,5,6,7,0,1,2]</code>.</p>

<p>Given the array <code>nums</code> <strong>after</strong> the possible rotation and an integer <code>target</code>, return <em>the index of </em><code>target</code><em> if it is in </em><code>nums</code><em>, or </em><code>-1</code><em> if it is not in </em><code>nums</code>.</p>

<p>You must write an algorithm with <code>O(log n)</code> runtime complexity.</p>

<p>&nbsp;</p>
<p><strong class="example">Example 1:</strong></p>
<pre><strong>Input:</strong> nums = [4,5,6,7,0,1,2], target = 0
<strong>Output:</strong> 4
</pre><p><strong class="example">Example 2:</strong></p>
<pre><strong>Input:</strong> nums = [4,5,6,7,0,1,2], target = 3
<strong>Output:</strong> -1
</pre><p><strong class="example">Example 3:</strong></p>
<pre><strong>Input:</strong> nums = [1], target = 0
<strong>Output:</strong> -1
</pre>
<p>&nbsp;</p>
<p><strong>Constraints:</strong></p>

<ul>
	<li><code>1 &lt;= nums.length &lt;= 5000</code></li>
	<li><code>-10<sup>4</sup> &lt;= nums[i] &lt;= 10<sup>4</sup></code></li>
	<li>All values of <code>nums</code> are <strong>unique</strong>.</li>
	<li><code>nums</code> is an ascending array that is possibly rotated.</li>
	<li><code>-10<sup>4</sup> &lt;= target &lt;= 10<sup>4</sup></code></li>
</ul>

33. Поиск в повернутом отсортированном массиве

Средний уровень сложности
<p>Имеется целочисленный массив <code>nums</code>, отсортированный в порядке возрастания (с <strong>различными</strong> значениями).</p>

<p>Перед передачей в вашу функцию массив <code>nums</code> может быть <strong>повернут влево</strong> по неизвестному индексу <code>k</code> (<code>1 <= k < nums.length</code>), так что результирующий массив будет <code>[nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]]</code> (<strong>индексация по 0</strong>). Например, массив <code>[0,1,2,4,5,6,7]</code> может быть повернут влево на <code>3</code> индексов и стать <code>[4,5,6,7,0,1,2]</code>.</p>

<p>Дано массив <code>nums</code> <strong>после</strong> возможного поворота и целое число <code>target</code>. Верните <em>индекс</em><code>target</code><em>, если он находится в </em><code>nums</code><em>, или </em><code>-1</code><em>, если он не находится в </em><code>nums</code>.</p>

<p>Необходимо написать алгоритм со сложностью выполнения <code>O(log n)</code>.</p>

<p>&nbsp;</p>
<p><strong class="example">Пример 1:</strong></p>
<pre><strong>Входные данные:</strong> nums = [4,5,6,7,0,1,2], target = 0
<strong>Выходные данные:</strong> 4
</pre><p><strong class="example">Пример 2:</strong></p>
<pre><strong>Входные данные:</strong> nums = [4,5,6,7,0,1,2], target = 3
<strong>Выходные данные:</strong> -1
</pre><p><strong class="example">Пример 3:</strong></p>
<pre><strong>Входные данные:</strong> nums = [1], target = 0
<strong>Выходные данные:</strong> -1
</pre>
<p>&nbsp;</p>
<p><strong>Ограничения:</strong></p>

<ul>

<li><code>1 <= nums.length <= 5000</code></li>

<li><code>-10<sup>4</sup> <= nums[i] <= 10<sup>4</sup>></code></li>

<li>Все значения <code>nums</code> являются <strong>уникальными</strong>.</li>

<li><code>nums</code> — это возрастающий массив, который может быть повернут.</li>

<li><code>-10<sup>4</sup> <= target <= 10<sup>4</sup>></code></li>
</ul>

<br> <hr> <br>

### Рішення та пояснення

```javascript
var search = function(nums, target) {
    let left = 0; // Ініціалізуємо лівий вказівник початком масиву
    let right = nums.length - 1; // Ініціалізуємо правий вказівник кінцем масиву

    while (left <= right) { // Виконуємо цикл, поки лівий вказівник не перетне правий
        let mid = Math.floor((left + right) / 2); // Знаходимо індекс середнього елемента

        if (nums[mid] === target) { // Якщо середній елемент є шуканою ціллю
            return mid; // Повертаємо його індекс
        }

        // Перевіряємо, чи відсортована ліва половина масиву
        if (nums[left] <= nums[mid]) {
            // Якщо ціль знаходиться в межах відсортованої лівої половини
            if (target >= nums[left] && target < nums[mid]) {
                right = mid - 1; // Звужуємо область пошуку, зсуваючи правий вказівник
            } else {
                left = mid + 1; // Інакше шукаємо в правій половині, зсуваючи лівий вказівник
            }
        } 
        // Якщо ліва половина не відсортована, то права половина точно відсортована
        else {
            // Якщо ціль знаходиться в межах відсортованої правої половини
            if (target > nums[mid] && target <= nums[right]) {
                left = mid + 1; // Звужуємо область пошуку, зсуваючи лівий вказівник
            } else {
                right = mid - 1; // Інакше шукаємо в лівій половині, зсуваючи правий вказівник
            }
        }
    }

    return -1; // Якщо елемент не знайдено після завершення циклу, повертаємо -1
};
```

**Складність алгоритму:**
- **Часова складність:** `O(log n)`. Оскільки на кожній ітерації ми відкидаємо половину масиву, це класичний бінарний пошук.
- **Просторова складність:** `O(1)`. Ми використовуємо лише кілька додаткових змінних для вказівників, тому витрати пам'яті не залежать від розміру масиву.

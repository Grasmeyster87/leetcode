3043. Find the Length of the Longest Common Prefix

Medium
<p>You are given two arrays with <strong>positive</strong> integers <code>arr1</code> and <code>arr2</code>.</p>

<p>A <strong>prefix</strong> of a positive integer is an integer formed by one or more of its digits, starting from its <strong>leftmost</strong> digit. For example, <code>123</code> is a prefix of the integer <code>12345</code>, while <code>234</code> is <strong>not</strong>.</p>

<p>A <strong>common prefix</strong> of two integers <code>a</code> and <code>b</code> is an integer <code>c</code>, such that <code>c</code> is a prefix of both <code>a</code> and <code>b</code>. For example, <code>5655359</code> and <code>56554</code> have common prefixes <code>565</code> and <code>5655</code> while <code>1223</code> and <code>43456</code> <strong>do not</strong> have a common prefix.</p>

<p>You need to find the length of the <strong>longest common prefix</strong> between all pairs of integers <code>(x, y)</code> such that <code>x</code> belongs to <code>arr1</code> and <code>y</code> belongs to <code>arr2</code>.</p>

<p>Return <em>the length of the <strong>longest</strong> common prefix among all pairs</em>.<em> If no common prefix exists among them</em>, <em>return</em> <code>0</code>.</p>

<p>&nbsp;</p>
<p><strong class="example">Example 1:</strong></p>

<pre><strong>Input:</strong> arr1 = [1,10,100], arr2 = [1000]
<strong>Output:</strong> 3
<strong>Explanation:</strong> There are 3 pairs (arr1[i], arr2[j]):
- The longest common prefix of (1, 1000) is 1.
- The longest common prefix of (10, 1000) is 10.
- The longest common prefix of (100, 1000) is 100.
The longest common prefix is 100 with a length of 3.
</pre>

<p><strong class="example">Example 2:</strong></p>

<pre><strong>Input:</strong> arr1 = [1,2,3], arr2 = [4,4,4]
<strong>Output:</strong> 0
<strong>Explanation:</strong> There exists no common prefix for any pair (arr1[i], arr2[j]), hence we return 0.
Note that common prefixes between elements of the same array do not count.
</pre>

<p>&nbsp;</p>
<p><strong>Constraints:</strong></p>

<ul>
	<li><code>1 &lt;= arr1.length, arr2.length &lt;= 5 * 10<sup>4</sup></code></li>
	<li><code>1 &lt;= arr1[i], arr2[i] &lt;= 10<sup>8</sup></code></li>
</ul>

3043. Знайдіть довжину найдовшого спільного префікса

Середній

<p><strong>Префікс</strong> додатного цілого числа — це ціле число, утворене однією або кількома його цифрами, починаючи з <strong>крайньої</strong> цифри. Наприклад, <code>123</code> є префіксом цілого числа <code>12345</code>, тоді як <code>234</code> <strong>не</strong> є.</p>

Наприклад, <code>5655359</code> та <code>56554</code> мають спільні префікси <code>565</code> та <code>5655</code>, тоді як <code>1223</code> та <code>43456</code> <strong>не</strong> мають спільного префікса.</p>

<p>Повернути <em>довжину <strong>найдовшого</strong> спільного префікса серед усіх пар</em>.<em> Якщо серед них немає спільного префікса</em>, <em>повернути</em> <code>0</code>.</p>

- Найдовший спільний префікс (1, 1000) дорівнює 1.
- Найдовший спільний префікс (10, 1000) дорівнює 10.
- Найдовший спільний префікс (100, 1000) дорівнює 100.
Найдовший спільний префікс дорівнює 100 з довжиною 3.

Зауважте, що спільні префікси між елементами одного масиву не враховуються.

## Розбір рішення

### Ідея
Замість перебору всіх пар `(x, y)` за `O(n·m)`, будуємо `Set` з усіх числових префіксів `arr1`.
Потім для кожного числа з `arr2` перевіряємо його префікси (від найдовшого до найкоротшого) — перший знайдений у `Set` і є найдовшим спільним.

**Ключова оптимізація**: при побудові `Set`, якщо префікс вже є — зупиняємось (`break`), бо всі коротші префікси гарантовано теж вже додані попередніми числами.

### Складність
- **Час**: `O((n + m) · d)`, де `d ≤ 9` — макс. кількість цифр
- **Пам'ять**: `O(n · d)` — для `Set` усіх унікальних префіксів

### Построковий розбір

> Оголошення функції з двома вхідними масивами.

---

```javascript
    const prefixes = new Set();
```
> Створюємо `Set` для зберігання всіх числових префіксів елементів `arr1`.
> `Set.has()` для цілих чисел (Smi) у V8 працює за `O(1)`.

---

```javascript
    for (let i = 0; i < arr1.length; i++) {
        let n = arr1[i];
```
> Ітеруємо по `arr1` класичним `for` (швидше за `for...of`, бо не створює ітератор).

---

```javascript
        while (n > 0) {
            if (prefixes.has(n)) break;
```
> **Головна оптимізація**: перед `add()` перевіряємо `has()`.
> Якщо число `n` вже в `Set` — значить **усі його коротші префікси теж вже є**
> (бо вони були додані при обробці попереднього числа, яке мало такий самий префікс).
> Це скорочує кількість `.add()` викликів у **3–5 разів** на типових даних.
>
> **Приклад**: `arr1 = [12345, 12367]`
> - Число `12345`: додаємо `12345 → 1234 → 123 → 12 → 1` (5 вставок)
> - Число `12367`: додаємо `12367 → 1236` → перевіряємо `123` → **вже є → break!** (лише 2 вставки замість 5)

---

```javascript
            prefixes.add(n);
            n = (n / 10) | 0;
```
> Додаємо число до `Set` і відрізаємо останню цифру.
> `(n / 10) | 0` — побітовий аналог `Math.floor(n / 10)`, але швидший,
> бо `| 0` — це одна інструкція процесора (truncate to int32),
> тоді як `Math.floor` — виклик функції з перевірками.
>
> **Приклад**: `12345 → 1234 → 123 → 12 → 1 → 0` (вихід з циклу)

---

```javascript
    let res = 0;
```
> Змінна для зберігання максимальної довжини знайденого спільного префікса.

---

```javascript
        let n = arr2[i];

```
> Для кожного числа з `arr2` перебираємо його префікси від найдовшого до найкоротшого.

---

```javascript
            if (prefixes.has(n)) {
```
> Перевіряємо чи цей префікс існує серед префіксів `arr1`.
> Оскільки ми йдемо від найдовшого до найкоротшого, перший знайдений — це і є
> найдовший спільний префікс для цієї пари.

---

```javascript
                const len = n < 10 ? 1 : n < 100 ? 2 : n < 1000 ? 3
                    : n < 10000 ? 4 : n < 100000 ? 5 : n < 1000000 ? 6
                    : n < 10000000 ? 7 : n < 100000000 ? 8 : 9;
```
> Підрахунок кількості цифр через ланцюг порівнянь — це `O(1)` за часом.
> Альтернатива `Math.floor(Math.log10(n)) + 1` вимагає два виклики `Math`-функцій,
> а ланцюг порівнянь компілюється у прості інструкції `cmp + branch`.

---

```javascript
                if (len > res) res = len;
                break;
```
> Оновлюємо максимум і виходимо з внутрішнього `while` — коротші префікси
> цього числа нас не цікавлять (вони завжди коротші за вже знайдений).

---

```javascript
            n = (n / 10) | 0;
```
> Якщо збігу не знайдено — відрізаємо останню цифру і пробуємо коротший префікс.

---

```javascript
        if (res === 9) return 9;
```
> **Ранній вихід**: числа мають максимум `9` цифр (`≤ 10⁸`).
> Якщо вже знайшли збіг довжиною `9` — довший неможливий, повертаємо одразу.

---

```javascript
    return res;
};
```
> Повертаємо довжину найдовшого спільного префікса, або `0` якщо збігів не було.

### Приклад трейсу

**Вхід**: `arr1 = [1, 10, 100]`, `arr2 = [1000]`

**Фаза 1 — побудова Set:**
| Число | Ітерації while | Set після |
|---|---|---|
| `1` | `1` → add, `0` → вихід | `{1}` |
| `10` | `10` → add, `1` → has → **break** | `{1, 10}` |
| `100` | `100` → add, `10` → has → **break** | `{1, 10, 100}` |

> Без дедуплікації було б 9 `.add()`, з дедуплікацією — лише **4**.

**Фаза 2 — пошук:**
| Число | Ітерації while | Результат |
|---|---|---|
| `1000` | `1000` → ні, `100` → **так!** → len=3 | `res = 3` |

**Відповідь**: `3`
